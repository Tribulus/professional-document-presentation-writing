# Professional Document & Presentation Writing Skill

一个面向学术与工作场景的 AI 文档写作及 PPT 制作 Skill，覆盖任务理解、需求澄清、写作规划、资料核查、内容生成、排版规范、演示文稿制作与交付检查。

适用于课程论文、研究报告、商业分析、竞品分析、产品与运营文档，以及 PowerPoint 演示文稿。

## 1. 主要功能

### 1.1 写作前的需求澄清与方向规划

对于主题不明确或尚未形成写作思路的任务，Skill 会先阅读用户提供的作业要求、参考资料和现有内容，再判断是否需要进一步澄清。

- 识别研究问题、受众、写作目标和任务限制。
- 对抽象问题提供具体、中立的示例，帮助用户理解不同选择。
- 提供 2—4 个具有实际差异的研究或写作方向，说明分析重点、证据需求和主要取舍。
- 允许用户选择、组合方向，或补充自己的初步想法。
- 将语言、字数、页数、引用格式等要求集中收集，减少重复提问。
- 对需要规划的任务，先确认大纲，再正式写作。

如果用户已经提供明确要求，则跳过不必要的澄清。

### 1.2 正文写作与语言优化

重点处理专业文档中常见的内容空泛、重复论证和过度自我限定问题。

- 删除没有实质信息增量的套话和防御性免责声明。
- 减少“本文仅讨论……不代表所有……”等重复叠甲。
- 将必要的范围、假设与适用条件直接融入事实描述。
- 优先通过具体机制、数据、案例和比较推进论证。
- 修改已有内容时保留原意，不擅自补充未经证实的工作成果或研究发现。

写作遵循以下优先级：

**准确性与证据完整性 > 有效论证 > 表达简洁 > 风格修饰。**

### 1.3 资料检索与引用核查

支持根据任务需要检索公开资料，并对引用进行核验。

- 优先使用原始研究、官方报告和原始数据。
- 不编造文献、作者、DOI、数据、案例或来源链接。
- 核查引用是否真正支持正文观点。
- 检查数据的时间、地区、样本、统计口径、单位及计算结果。
- 区分原始事实、自行计算、合理推论和待验证假设。
- 引用格式优先遵循学校或项目要求；未指定时使用数字上标和文末参考文献。
- 对无法核实的内容予以说明或调整，不将其作为确定事实。

### 1.4 文档排版

提供默认的中英文文档排版规范：

- 中文：微软雅黑，中文全角标点。
- 英文：Times New Roman，英文半角标点。
- 中英混排根据实际语境处理。
- 支持 1、1.1、1.1.1 等多级标题编号。
- 优先使用文档原生标题样式，方便后续修改。
- 用户提供的作业规范或文档模板优先于默认设置。

对于适合使用图表或示意图的内容，可保留图表占位，并说明建议的制作形式、所需数据及用途。

### 1.5 PPT 大纲规划与内容密度

制作 PPT 前，默认先提供整体结构和逐页计划，供用户调整。

逐页计划包含：

- 页面标题与主要内容。
- 核心观点或需要解释的问题。
- 推荐的图表、流程图、配图及布局方式。
- 页面信息密度。
- 建议演讲时长。
- 需要进一步核实的资料。

用户可以选择三种整体信息密度：

| 模式 | 特点 |
| --- | --- |
| 更多文字 | 保留较多解释、案例与证据，适合研究型汇报 |
| 适中（默认） | 结合图表与必要分析，兼顾信息量和阅读体验 |
| 更简洁 | 突出关键观点与证据，将部分讲解放入演讲者备注 |

不同页面可采用不同密度，不强制统一字数或元素数量。

用户确认整体大纲后再生成 PPT，减少因结构变化造成的重复制作。

### 1.6 PPT 可编辑图形与数据可视化

优先使用 PowerPoint 内可编辑的元素呈现内容。

- 使用矢量形状制作流程图、结构图、时间线、关系图等。
- 使用原生图表呈现数据比较、时间趋势、比例和分布。
- 根据内容需要配置图标、箭头、分区和信息卡片。
- 对于复杂产品外观、真实场景、平台界面或原始证据，使用适当的外部图片。
- 尽可能保留文本、图表及图形的位置、字体、颜色和大小的可编辑性。

配图和图标以解释内容为目的，不为填充空白而强制添加。

每页涉及外部资料时，在页面底部以小字列出对应来源，并提供原文链接。

### 1.7 演示时长与 Speaker Notes

根据总演示时长、内容复杂度及页面重要性，为各页分配建议讲述时间。

正式生成 PPT 时，为每页添加 PowerPoint 原生 Speaker Notes，默认包括：

- 本页核心信息。
- 分点讲述提纲。
- 关键概念、数据或图表的解释。
- 与下一页的过渡。
- 本页建议演讲时长。

默认提供结构化提纲；如果需要，可另行要求完整演讲稿。

涉及视频、产品演示、互动或问答时，会将这些环节纳入总时长规划。

### 1.8 交付前检查

文档检查包括内容完整性、语言、论证逻辑、事实、数据、引用、编号和排版。

PPT 额外检查页面布局、文字溢出、图表准确性、来源可读性、视觉一致性、图形可编辑性及演讲备注。

正式内容与审查说明分开，必要时单独列出未核实的资料和待补充事项。

### 1.9 多人协作合稿与一致性审查

- 检查合并后的 Word 报告或 PPT，定位跨段、跨章或跨页的术语差异、重复内容、数据与结论冲突，以及引用、图表和演讲者备注的不一致。
- 用稳定编号关联每项问题的原句、数值及全部相关位置，并给出修改建议。术语索引列出各写法的核实次数、每次出现的位置和上下文。统一前先核对定义和统计口径。
- 可交付问题清单、带高亮和批注的独立审阅副本，或两者同时交付。原稿保留，正文修改需另行授权。工具无法生成或验证原生批注时，提供独立标记版或逐位置清单。

## 2. 如何使用

安装后，直接使用自然语言描述任务即可。Skill 根据任务内容判断是否适用，并选择相应工作模式。

**探索模式**

适合尚未确定主题、研究问题或写作方向的情况。

示例：

“这是老师布置的课程论文要求，帮我看看有哪些可行的研究方向，先不要写正文。”

Skill 会阅读要求、帮助澄清关键问题、提供研究方向，并在确认大纲后进入写作。

**执行模式**

适合已有明确大纲和任务要求的情况。

示例：

“按照这份大纲和参考资料写一篇英文研究报告，引用需要可追溯，完成后检查文献和数据口径。”

Skill 会根据已有要求直接执行，不重复询问已经明确的事项。

**PPT 模式**

示例：

“根据这份研究报告制作一套 15 分钟的课程展示 PPT。先给我逐页大纲、配图建议和时间分配，确认后再生成。”

Skill 会规划内容结构、视觉表达、页面密度和演讲时间，并在正式制作时添加相应备注。

**局部修改模式**

示例：

“检查这份报告有没有重复叠甲和空泛表述，只修改这些地方，不改变原有论点。”

“把 PPT 第 5 页的流程图改成可编辑图形，同时检查引用和 Speaker Notes。”

局部修改任务无需重新完成整套规划流程。

**合稿审查**

“检查这份小组报告的术语、数据和结论。请列出所有相关原文位置，同时给我问题清单和带批注的 Word 审阅副本。”

## 3. 使用建议

提供作业要求、评分标准、企业模板、已有研究资料或初步想法，有助于获得更符合实际需求的结果。

对于需要外部证据的内容，建议保留核查与自检步骤。

涉及 PPT 制作时，建议提供总演示时长、受众，以及已有模板（如有）。如果暂时没有明确想法，可以先使用方向探索功能。

## 4. 注意事项

- Skill 不保证所有来源都可以访问，受限资料可能需要用户提供。
- 不能核实的资料不会被视为已验证证据。
- 可编辑图表、矢量图和原生 Speaker Notes 的实际生成能力取决于执行环境及所使用的文件工具。
- 用户提供的学校、公司或项目规范优先于 Skill 默认规则。
- 对于明确且简单的局部任务，不强制执行完整的需求澄清流程。
